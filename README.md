# Customer Churn Prediction & Retention Intelligence System

A machine-learning workflow for analysing telecommunications customer churn, comparing predictive models, interpreting model behaviour, and exploring customer retention actions.

## Project contents

- `notebooks/customer_churn_analysis.ipynb` — Colab/Jupyter analysis and modelling workflow.
- `data/` — supplied Telco churn dataset files.
- `src/app.py` — FastAPI prediction API.
- `models/` — serialized feature pipeline and trained model artifacts supplied with the project.
- `reports/model_metrics.csv` — recorded validation metrics.
- `reports/drift_report.csv` — recorded KS-test drift checks.

## Run the notebook in Google Colab

1. Open the notebook in `notebooks/` using Google Colab.
2. Upload `data/Telco_customer_churn.xlsx` to the Colab session's `/content/` directory, because the notebook currently reads `/content/Telco_customer_churn.xlsx`.
3. Run the notebook cells in order.
4. Review the validation metrics and plots generated by the notebook.

## Run the API locally

Use Python 3.10 or 3.11 in a virtual environment. Install dependencies:

```bash
pip install -r requirements.txt
```

Start the API from the repository root:

```bash
uvicorn src.app:app --reload
```

The API loads the supplied model artifacts from `models/`. The prediction endpoint is `POST /predict`; interactive API documentation is available at `/docs`.

## Dependencies

See `requirements.txt`. The serialized model artifacts should be loaded with compatible versions of their original Python dependencies.

## Notes and limitations

- The notebook uses a fixed Colab path for the Excel dataset; see the instructions above.
- The API is a project implementation and should be tested end-to-end in the target environment before deployment.
- The drift report compares the supplied training and validation distributions; it is not evidence of live production monitoring.
- Retention recommendations are rule-based examples, not experimentally validated business interventions.
- Dataset contents are included as supplied; confirm dataset redistribution terms before making the repository public.
